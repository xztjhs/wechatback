## 1. 微信 4.x 数据库

### 1.1 目录

```text
xwechat_files\
└─ wxid_xxx_<suffix>\
   └─ db_storage\
      ├─ message\        message_0..N.db, message_fts.db, message_resource.db
      ├─ contact\        contact.db, contact_fts.db
      ├─ session\        session.db
      ├─ favorite\       favorite.db
      ├─ sns\            sns.db
      ├─ emoticon\       emoticon.db
      ├─ head_image\     head_image.db
      ├─ hardlink\       hardlink.db
      ├─ media\          （4.x 部分版本）
      └─ ...
```

### 1.2 `contact.db`

表 `contact`：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | 自增 |
| `username` | TEXT | wxid / 群 id / 公众号 id |
| `nick_name` | TEXT | 昵称 |
| `remark` | TEXT | 备注（显示名优先） |
| `alias` | TEXT | 微信号 |
| `flag` | INTEGER | 位掩码，`flag & 3 != 0` 表示好友 |
| `verify_flag` | INTEGER | 正常联系人通常为 0 |
| `big_head_url` / `small_head_url` | TEXT | 头像 URL |
| `description` | TEXT | 签名 |

显示名优先级：`remark` > `nick_name` > `alias` > `username`。

群聊另有 `chat_room` 表（群成员、群主等），具体列名待实测。

### 1.3 `message_N.db`

#### 表名

```text
Msg_<md5(username)>
```

例：`username = "123456789@chatroom"` → `Msg_<md5 的 32 位小写 hex>`。

> 同一个会话的消息可能分布在多个 `message_N.db`；每个库都可能有同名表。

#### 列

| 列 | 类型 | 说明 |
|---|---|---|
| `local_id` | INTEGER PK | 库内自增；跨库不可直接比较 |
| `server_id` | INTEGER | 服务端 id；跨库去重优先用它 |
| `local_type` | INTEGER | 消息类型，见 1.4 |
| `sort_seq` | INTEGER | 排序序号 |
| `real_sender_id` | INTEGER | 指向**本库** `Name2Id.rowid` |
| `create_time` | INTEGER | Unix 秒（北京时间） |
| `status` | INTEGER | 消息状态（发送中/已发送/已读等） |
| `message_content` | TEXT/BLOB | 正文；可能 zstd 压缩 |
| `compress_content` | TEXT | 压缩内容备用 |
| `packed_info_data` | BLOB | protobuf 附件元数据（图片/文件等） |
| `WCDB_CT_message_content` | INTEGER | `4` = zstd 压缩 |

#### `Name2Id`

| 列 | 说明 |
|---|---|
| `user_name` | 微信号/wxid |
| `is_session` | 是否会话参与者 |
| `rowid` | 本库内的数字 id，`real_sender_id` 指向它 |

**关键**：`real_sender_id` 只在当前库有意义；跨库必须用各自库的 `Name2Id` 重新解析。

### 1.4 消息类型 `local_type`

**重要**：`local_type` 是位打包值，不是单纯的类型数字：

```python
base_type = local_type & 0xFFFFFFFF
subtype   = local_type >> 32
```

例如 `25769803825` = `(6 << 32) | 49`，即“文件”消息；`21474836529` = `(5 << 32) | 49`，即“链接”。

| base_type | 类型 | 归档处理 |
|---|---|---|
| 1 | 文本 | 直接导出 |
| 3 | 图片 | 解密 `.dat` + 缩略图 |
| 34 | 语音 | 占位 `[语音 Ns]`（不在导出范围） |
| 43 | 视频 | 去重复制 + Obsidian 链接 |
| 47 | 表情/贴纸 | 能解则解，否则 `[表情]` |
| 48 | 位置/其他 | 占位 |
| 49 | 富媒体 | 链接/文件/红包/转账，按 `subtype` + XML 再分 |
| 10000 | 系统消息 | callout |
| 其他 | 未知 | 保留原文 + `[未知类型]` |

`base_type=49` 的常见 `subtype`：

| subtype | 含义 | 处理 |
|---|---|---|
| 1 | 名片/文本卡片 | 标题 + 描述 |
| 4 | 视频号/外部分享 | 标题 + 链接 |
| 5 | 链接 | 标题 + 摘要 + URL |
| 6 | 文件 | 标题 + 大小 + 本地文件 |
| 33 | 小程序/公众号卡片 | 标题 |
| 36 | 小程序 | 标题 |
| 51/63 | 视频号直播/更新提示 | 标题 + 描述 |
| 53 | 接龙 | 标题（正文） |
| 57 | 引用回复 | 引用 + 正文 |
| 62 | 拍一拍 | 系统提示 |
| 2000/2001 | 转账/红包 | 占位 |

### 1.5 内容压缩

```python
if row["WCDB_CT_message_content"] == 4:
    content = zstandard.decompress(row["message_content"]).decode("utf-8", "replace")
else:
    content = row["message_content"].decode("utf-8", "replace")
```

### 1.6 图片/视频/文件的 content 字段（已实测）

**图片（base_type=3）**：

- `message_content` 是 `<msg><img ... length="..." md5="..." ...></img></msg>`；
- `packed_info_data` 末尾有 32 位 ASCII hex，**这才是本地文件名**；
- 本地路径：

```text
图片：msg\attach\<md5(chat_id)>\<YYYY-MM>\Img\<packed_md5>.dat
缩略图：同目录 <packed_md5>_t.dat
高清：同目录 <packed_md5>_h.dat
```

**视频（base_type=43）**：

- `message_content` 是 `<msg><videomsg ... newmd5="..." rawmd5="..." ...></videomsg></msg>`；
- `packed_info_data` 末尾的 32 位 ASCII hex 是本地文件名；
- 路径：`msg\video\<YYYY-MM>\<packed_md5>.mp4`。

**文件（base_type=49, subtype=6）**：

- `message_content` 是 `<appmsg><title>文件名</title><type>6</type><appattach><totallen>...</totallen><fileext>...</fileext></appattach><md5>...</md5></appmsg>`；
- XML 里的 `md5` 与 `hardlink.db.file_hardlink_info_v4.md5` 对应；
- 路径：`msg\file\<YYYY-MM>\<title>`；`hardlink.db` 的 `dir1`（经 `dir2id` 映射）给出月份。

**通用**：

- `md5(chat_id)` 就是 `Msg_<hash>` 表的后缀；
- `hardlink.db` 的 `dir2id` 行号映射：图片 `dir1=chat_hash, dir2=month`；视频/文件 `dir1=month, dir2=0`；
- 若直接路径不存在，用 `message_resource.db` 或 `hardlink.db` 兜底。

### 1.7 `message_fts.db`（快捷通道，非事实源）

- 表 `message_fts_v4_0` ~ `message_fts_v4_N`（分片，必须全部遍历）。
- 列 `acontent` 已是解码后的文本；`session_id` / `sender_id` 指向 `name2id.rowid`。
- 适合快速做文字检索；**不适合**做完整导出（缺媒体元数据、类型、部分系统消息）。
- `name2id` 表只在这个库里有完整映射；不要用 `message_resource.db` 的 `ChatName2Id` / `SenderName2Id` 做全量解析。

## 2. 图片 `.dat` V2 格式

```text
┌──────────────┬────────────────────────────────┬──────────────┐
│ 15B header   │ AES-128-ECB 段                  │ XOR 段        │
│ <6sLLx>      │ aes_size + 16 字节              │ xor_size 字节 │
└──────────────┴────────────────────────────────┴──────────────┘
```

| 字段 | 值/说明 |
|---|---|
| 签名 | `07 08 56 32 08 07`（V2）；V1 为 `07 08 56 31 08 07`；V3 为 3.x 整文件 XOR |
| `aes_size` | 小端 u32；本机样本 1024；**实际 AES 段 = aes_size + 16** |
| `xor_size` | 小端 u32；本机样本 74199 |
| AES | AES-128-ECB；解密后做 PKCS#7 unpad |
| XOR | 单字节；key = `UIN & 0xFF` |
| V1 硬编码 key | `cfcd208495d565ef`（`md5("0")[:16]`） |
| V2 账号 key | `MD5(UIN + wxid)[:16]` 的 ASCII 字节；UIN 来自 `kvcomm/key_<UIN>_*.statistic` 文件名 |
| WXGF | 载荷可能是 HEVC；扫描起始码后用 ffmpeg 转 PNG（首帧） |

### 3.6 `messages_fts`

```sql
CREATE VIRTUAL TABLE messages_fts USING fts5(
  content, sender_name, chat_name,
  tokenize='trigram'
);
```

- 3 个汉字以上：`MATCH '"关键词"'`；
- 2 个汉字：`LIKE '%关键词%'`；
- 英文/数字：trigram 同样可用（≥3 字符）。

## 7. 约定

### 7.1 时间

- 源：Unix 秒，北京时间（UTC+8）。
- 归档：`ts`（int）+ `time_iso`（带 `+08:00`）。
- Markdown：`HH:mm`，日期标题 `## YYYY-MM-DD`。

### 7.2 ID

| 对象 | 规则 |
|---|---|
| 消息 | `server_id > 0` 用 `srv:<chat_id>:<server_id>`；否则 `loc:<chat_id>:<shard>:<local_id>` |
| 媒体 | 解码后字节的 SHA-256 |
| 会话 | `chat_id` 原样 |
| 笔记 | `<chat_id>|<YYYY-MM>|<chunk>` |

### 7.3 状态

| 值 | 含义 |
|---|---|
| `active` | 正常 |
| `recalled` | 微信中已撤回，归档保留原文 |
| `missing` | 源库已无此行（被删除） |
| `edited` | 内容与首次导出不同 |
| `failed` | 解密/解析失败 |
