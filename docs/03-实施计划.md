## 2. P1：环境、密钥、样本（Go / No-Go）

### 2.1 环境

- 用 `uv` 创建 Python 3.11 环境：
  ```powershell
  uv venv
  uv pip install pycryptodome pillow zstandard
  ```
- 安装 ffmpeg：
  ```powershell
  winget install Gyan.FFmpeg
  ```
- 确认管理员权限（VSS、进程内存读取需要）。
- `wechatback doctor` 检查：
  - 微信版本、进程、数据目录、账号；
  - `Weixin.exe` 是否运行；
  - `db_storage` 是否可读；
  - ffmpeg 是否在 PATH；
  - VSS 是否可用；
  - SQLite 是否支持 FTS5 trigram。

### 2.2 DB key

- 运行 `wcdb-key-tool` 的 Windows 版 `extract`（管理员 + 微信登录）。
- 预期输出 `all_keys.json`，覆盖 `db_storage` 下所有 `.db`。
- 用 HMAC 校验结果；对每个 db 试开，确认 `SELECT count(*) FROM sqlite_master` 正常。
- **Go 条件**：`message_0..6.db`、`contact.db`、`session.db` 全部有 key 且能打开。

### 2.3 图片 key

- 用 `decrypt_wx_img_dat` 的提取器（或等价脚本）从 `Weixin.exe` 内存提取 16 字符 AES key。
- 用 20 个 `.dat` 样本（含 `_t`、`_h`、普通图）做完整解码 + PIL 校验。
- **Go 条件**：20/20 成功，或至少 19/20 且失败样本可解释（源文件损坏）。
- **No-Go 处理**：换提取器/手工定位；仍失败则先交付文字 + 图片占位，图片作为二期。

### 2.4 消息映射样本

打印 20 条 type=3/43/49 的原始行：

- `message_content` 原文（XML/JSON/protobuf）；
- `packed_info_data` 十六进制前 128 字节；
- `local_type`、`create_time`、`real_sender_id`；
- 对应的本地文件是否存在。

产出 `docs/samples/message-mapping.md`（**只放字段名和结构，不放真实聊天内容**）。

**Go 条件**：能稳定解析出图片/视频/文件的本地路径或 md5；否则调整映射策略。

## 3. P2：DB 解密 + 消息归一

### 3.1 解密

- 读取 `all_keys.json`，按 salt 选择 key。
- 解密 `message_*.db`、`contact.db`、`session.db`、`message_resource.db`。
- 输出到 `%TEMP%\wechatback\decrypted\<run-id>\`，跑完删除。
- 每个库解密后用 `PRAGMA integrity_check` 验证。

### 3.2 归一

- 建 `archive.db`。
- 遍历所有 `message_*.db` 的 `Msg_*` 表：
  - 解析 `real_sender_id`（每库自己的 `Name2Id`）；
  - 解 zstd；
  - 按 `local_type` 转成统一记录；
  - `server_id` 优先做 `msg_id`；
  - 写入 `messages`。
- 刷新 `contact.db` / `session.db` 到 `chats`。
- 生成 `export/messages.jsonl`（可选）。

### 3.3 验收

- 每个 `Msg_*` 表的源行数与归档行数对比表。
- 差异清单（重复 server_id、空 content、未知类型）。
- 随机 20 条与微信 UI 对照。

## 4. P3：Obsidian 渲染

- 实现 `renderer`：
  - 按 `(chat_id, month)` 分组；
  - 生成 frontmatter + 日期标题 + 消息行；
  - 转义、换行、引用、系统消息、撤回标记；
  - 原子写；
  - 内容哈希不变则跳过。
- 生成 `30_Index` 三个笔记。
- 验收：
  - 打开 Vault，随机 5 个会话可读；
  - 中文关键词搜索命中；
  - Dataview 表格能列出会话；
  - 月份文件大小合理（单文件 < 5 MB）。

---

## 5. P4：图片解密 + 缩略图

- 实现 `media_image`：
  - V2 解码；
  - WXGF → ffmpeg；
  - 缩略图；
  - SHA-256 去重；
  - 与消息关联。
- 先跑 200 张样本，统计成功率；再跑全量。
- 验收：
  - 成功率 ≥ 99%；
  - Vault 无 `.dat`；
  - 50 张随机图在 Obsidian 显示；
  - 重复图只存一份。

---

## 6. P5：视频/文件去重 + 网关

- 实现 `media_file`：
  - 解析 type=43/49；
  - 计算 SHA-256（缓存）；
  - 写 `manifest.db`；
  - 去重。
- 实现 `serve`：
  - `GET /media/<sha256>`；
  - Range；
  - `Content-Disposition`；
  - `GET /health`。
- 验收：
  - 同一视频两个群 → 一条清单、两个链接；
  - 视频可拖动；
  - 缺失文件 404 + 标记。

---

## 7. P6：增量 + 调度 + 验收

- 实现 `export --incremental`：
  - 水位 + 7 天回看；
  - 新分片发现；
  - 新会话；
  - 撤回/编辑；
  - 只重渲染受影响月份。
- 计划任务：
  - `WeChatBack-Incremental` 每日 12:30；
  - `WeChatBack-Reconcile` 每月第一个周日；
  - `WeChatBack-Gateway` 登录时。
- 验收：
  - 测试群发消息 → 5 分钟内出现；
  - 撤回 → 原文 + 标记；
  - 新群 → 自动建目录；
  - 源数据抽样哈希不变；
  - VSS 无残留。

## 8. 测试策略

### 8.1 合成样本（进仓库）

- 用已知 PNG 生成 V2 `.dat`（15B 头 + AES + 标记 + XOR），验证解密器逐字节还原。
- 合成 SQLite：建 `Msg_*`、`Name2Id`、`contact` 最小表，验证归一/渲染。
- 合成 WXGF：用 ffmpeg 生成 HEVC 裸流，验证转码分支。
- **所有 fixtures 不含真实聊天内容。**

### 8.2 真实样本（不进仓库）

- 20 条消息、20 张图、5 个视频、5 个文件。
- 只在本地跑，输出报告不含原文（只含类型、大小、成功/失败）。

### 8.3 回归

- 每次改解析器，先跑合成样本 + 200 张真实图抽样。
- 微信升级后，先跑 `doctor` + 样本，再决定是否全量。

## 10. 风险控制

- **先样本后全量**：任何批处理先 20/200 条。
- **可回退**：`archive.db` 和 Vault 都是可重建的；原始数据不动。
- **不静默失败**：每个失败样本进 `quarantine`，有原因、有原路径。
- **版本锁定**：记录微信版本、工具版本、解密参数；升级后重新验证。
- **密钥备份**：`db_keys.json` 和 `image_key.json` 离线备份一份（加密），避免重装后无法解密历史库。
