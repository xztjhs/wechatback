# WeChatBack 运维手册

> 版本：v0.1（2026-10-22）
> 适用：Windows 11 + 微信 4.1.15.13 + Obsidian

---

## 1. 日常命令

```powershell
# 环境自检
wechatback doctor

# 首次：提取 DB key（管理员，微信保持登录）
wechatback key refresh

# 首次：提取图片 key（管理员，微信保持登录）
wechatback image-key probe

# 首次全量导出
wechatback export --full

# 日常增量
wechatback export --incremental

# 微信里下载了缺失的视频/文件后，重置 missing 并补跑
wechatback retry-missing --kind video
wechatback retry-missing --kind file
wechatback media --skip-images

# 只重渲染某个会话的某个月
wechatback render --chat "123456789@chatroom" --month 2026-10

# 启动媒体网关
wechatback serve

# 命令行检索
wechatback search "智算中心"

# 验收检查
wechatback verify

# 只检查源数据未被修改
wechatback verify --no-write
```

## 1.1 工作库与备份库（2026-10-23 调整）

| 角色 | 路径 | 用途 |
|---|---|---|
| 工作库 | `D:\WeChatBackVault` | Obsidian 打开这个；本地 NVMe，索引快 |
| 备份库 | `\\NAS\Backup\WeChatBack` | 冷备；不要用 Obsidian 直接打开 |

同步（本地 → NAS，默认只复制新增/变化，不删除）：

```powershell
powershell -ExecutionPolicy Bypass -File "D:\Tools\WeChatBack\scripts\sync-vault.ps1"
```

需要严格镜像时加 `-Mirror`（会删除 NAS 上本地不存在的文件，慎用）。

> 为什么改：NAS 是 SMB，Vault 有 405,303 个文件，Obsidian 启动索引会卡住；本地复制后正常。

## 2. 首次上线顺序

1. `wechatback doctor` —— 全绿。
2. `wechatback key refresh` —— 生成 `secrets\db_keys.json`。
3. `wechatback image-key probe` —— 20 张样本通过。
4. `wechatback export --full --limit 20` —— 只导 20 条，检查 Vault。
5. `wechatback export --full` —— 全量。
6. `wechatback verify` —— 对照验收标准。
7. 注册计划任务。

> 第 4 步是硬门槛：20 条不过，不要跑全量。

## 3. 计划任务（当前为手动模式）

**已确认 D3 = 手动**：不注册自动任务；需要时运行 `wechatback export --incremental`。
以下任务模板保留，未来想自动化时再启用。

| 任务名 | 触发 | 命令 | 权限 |
|---|---|---|---|
| `WeChatBack-Incremental` | 每日 12:30 | `wechatback export --incremental` | 管理员（VSS） |
| `WeChatBack-Reconcile` | 每月第一个周日 03:00 | `wechatback export --reconcile` | 管理员 |
| `WeChatBack-Gateway` | 用户登录时 | `wechatback serve --daemon` | 当前用户 |

注册示例：

```powershell
$action = New-ScheduledTaskAction -Execute "C:\path\to\wechatback.exe" -Argument "export --incremental"
$trigger = New-ScheduledTaskTrigger -Daily -At 12:30
Register-ScheduledTask -TaskName "WeChatBack-Incremental" -Action $action -Trigger $trigger -RunLevel Highest
```

> 如果不想让计划任务常驻管理员，可把 VSS 改为“临时副本”模式；一致性略降，靠 7 天回看补齐。

## 4. Obsidian 设置

1. 打开 Obsidian → “打开本地仓库” → 选 `D:\WeChatBackVault`。
2. 设置 → 文件与链接：
   - 新建链接格式：**相对路径**
   - 自动更新内部链接：开
3. 安装 Dataview（可选）：社区插件 → 浏览 → Dataview → 安装 → 启用。
4. 安装 Omnisearch（可选，大 Vault 更快）。
5. 打开 `30_Index\会话总览.md` 验证 Dataview 表格。
6. 搜索测试：`Ctrl+Shift+F` → 输入一个客户名或项目关键词。

## 5. 媒体网关

- 默认地址：`http://127.0.0.1:8765`
- 健康检查：`http://127.0.0.1:8765/health`
- 视频链接：`http://127.0.0.1:8765/media/<sha256>`
- 下载链接：`http://127.0.0.1:8765/media/<sha256>?download=1`

启动：

```powershell
wechatback serve
```

开机自启：

- 任务计划程序 → 创建任务 → 触发器“登录时” → 操作 `wechatback serve --daemon`。
- 或把快捷方式放进 `shell:startup`。

排障：

| 现象 | 处理 |
|---|---|
| 链接打不开 | 确认 `serve` 在跑；`curl http://127.0.0.1:8765/health` |
| 视频不能拖 | 确认服务支持 Range；用浏览器直接打开链接测试 |
| 404 | 源文件可能被移动/删除；查 `manifest.db` 的 `status` |
| 端口冲突 | 改 `config.toml` 的 `gateway.bind` |

## 6. 故障处理

### 6.1 `doctor` 报微信未运行

- 启动微信并登录；DB key 和图片 key 都依赖进程内存。

### 6.2 `key refresh` 命中 0

- 确认是 `Weixin.exe`（4.x），不是 `WeChat.exe`（3.x）。
- 确认以管理员运行。
- 确认微信版本未超过工具适配；查看工具输出的 `needle → node → candidate` 计数。
- 仍失败：用 x64dbg/Frida 按 `com.Tencent.WCDB.Config.Cipher` 对象链手工定位；或回退到官方备份 + 重点会话手工导出。

### 6.3 图片解码失败率高

- 先确认图片 key 是否通过 PIL 校验（不是“魔数对了”）。
- 检查 `.dat` 签名：V1/V2/V3 分支是否走对。
- 检查 16 字节固定标记是否被误拼进图片。
- 检查 JPEG 尾部 `FF D9` 截断。
- 检查 WXGF 分支 ffmpeg 是否在 PATH。
- 单张失败进 `quarantine`，不阻塞。

### 6.4 消息数对不上

- `message_fts.db` 只用于检索，不作为全量依据。
- 检查是否只扫了第一个分片；必须遍历 `message_fts_v4_0..N` 或所有 `message_N.db`。
- 检查 `server_id` 去重是否误合并。
- 检查 `WCDB_CT_message_content=4` 的 zstd 是否解压。
- 检查 `verify_flag` / 空 content 的过滤是否过严。

### 6.5 增量重复

- 检查 `msg_id` 是否稳定（`server_id` 优先）。
- 检查 `chat_state.last_ts` 是否被错误推进。
- 重跑一次全量对账，按 `msg_id` 去重。

### 6.6 Obsidian 卡顿

- 2026-10-23 已切换为 **本地工作库 `D:\WeChatBackVault` + NAS 冷备**；不要用 Obsidian 直接打开 `\\NAS\Backup\WeChatBack`。
- 如本地仍卡：设置 → 文件与链接 → 排除文件，加入 `20_Media`；关闭不必要的插件；不要开启 “Detect all extensions”。
- 本地工作库同步回 NAS：
  ```powershell
  powershell -ExecutionPolicy Bypass -File "D:\Tools\WeChatBack\scripts\sync-vault.ps1"
  ```

### 6.7 media 行存在但文件缺失

- 症状：`media` 表有记录，`export_path` 指向的文件不存在。
- 原因：SMB 客户端 `Path.exists()` 可能命中旧缓存，导致 `if not out.exists()` 跳过写入（2026-10-23 已修复为始终写入/复制）。
- 处理：把对应 `pending_media` 行重置为 `pending`（或按 `media_id` 重置），再运行：
  ```powershell
  wechatback media --skip-files
  ```
  补跑图片；视频/文件用 `retry-missing` + `media --skip-images`。

### 6.8 源数据被修改的怀疑

- 跑 `wechatback verify --no-write`，对比抽样文件的 `(size, mtime, sha1_head)`。
- 确认没有对源目录执行 `robocopy /MIR`、`VACUUM`、`checkpoint`。
- VSS 快照是否已删除：`vssadmin list shadows`。

## 7. 微信升级后的检查清单

1. 记录旧版本号、工具版本、解密参数。
2. 升级后先跑 `wechatback doctor`。
3. 跑 20 条消息 + 20 张图样本。
4. 检查 `.dat` 签名是否仍为 V2、16 字节标记是否变化。
5. 检查 `Msg_*` 列名/类型是否变化。
6. 通过后再跑增量；失败则回退工具版本或等待适配。

## 8. 密钥管理

- `secrets\db_keys.json`：per-salt key；新增 DB 分片可能产生新 salt，需要重新 `key refresh`。
- `secrets\image_key.bin`：DPAPI 加密；换 Windows 用户/重装系统后无法解密，需重新提取。
- 离线备份：把 `secrets\` 用 7z AES-256 加密后放离线介质；不要把密码和备份放一起。
- 不要提交到 Git、不要放 Vault、不要放云同步盘。

---

## 9. 日志与报告

- 每次运行：`%USERPROFILE%\.wechatback\logs\run-YYYYMMDD-HHMMSS.json`
  - 统计：消息数、图片数、失败数、耗时；
  - **不含聊天原文**，只含 ID/类型/大小/错误码。
- 失败样本：`quarantine\<sha1>.json`
  - 原路径、错误原因、可重试标记。
- 验收报告：`verify` 生成，含抽样结果和源数据哈希对比。

---

## 10. 回滚

- 归档可重建：删掉 `archive.db` 和 Vault 里的 `10_Chats`/`20_Media`，重跑全量。
- 不要删原始微信数据。
- 保留最近 3 次 `logs` 和 `state.db` 备份，便于定位增量问题。
- 如果新版本导出异常，回退到上一个工具版本 + 旧 `state.db`，先跑增量补齐。
